# Release audit — 2026-11-06

Target: WoW Forever 1.60.1.70790 (Interface 16001). Workspace: F:\\forever_multimonitor_addon. The findings below are based on the source/control flow, local Lua 5.1 runtime tests, .NET helper tests and one reversible real WoW HWND round trip. They are not proof that the in-game addon has passed the release matrix.

## Confirmed and fixed

| Priority | Reproducible scenario | Downstream impact | Mitigation | Evidence |
|---|---|---|---|---|
| P0 | Viewport:Apply returns false while pcall succeeds | Init formerly routed panels and wrote applied-state data without a valid cropped world viewport | Require actual true return, abort routing, restore raw mouse | Runtime fault-injection test |
| P0 | WorldFrame:SetPoint raises after ClearAllPoints / first SetPoint | Previously left a partially modified viewport, preventing safe play | Transactional anchor mutation with previous-state rollback and explicit failure | Runtime injected second-anchor failure |
| P1 | A panel SetPoint throws after ClearAllPoints and SetScale | Panel could remain offscreen or at incorrect scale | Restore pre-operation anchor points and scale; report failure | Runtime injected panel-anchor failure |
| P1 | UISpecialFrames contains two WorldMapFrame entries | Previous algorithm removed both but restored only one | Record and restore all removed indices, no duplicates on repeated Sync/Restore | Lua regression with duplicate entries |
| P1 | Windows-helper native window paths were documented but unverified | Users could not know if restore worked on a live HWND | Place/restore tested against running Wow.exe on two displays | Live helper output: placed 4480x1080, restored via primary fallback |

## Additional confirmed native concurrency defect — fixed

Two nearly simultaneous `place` invocations could both observe absent `window-state.json`, then overwrite the same `.new` file or replace the recovery state. The second launch could permanently discard the first launch's original placement. Fixed using a unique temporary file and atomic non-overwriting `File.Move`. Concurrent actual-process fault injection is not yet performed; the code path has been inspected and the native helper rebuilt.

## Confirmed feature gaps — not silently represented as fixed

- Native mainhand auto-calibration only supports exactly two horizontally adjacent, vertically aligned monitors. Stacked, nonadjacent or offset topologies require manual configuration. A generic left/right percentage cannot map these correctly.
- The automatic panel drag-position recorder depends on frames actually invoking native OnDragStop. UI elements moved through alternate mechanisms do not necessarily persist.
- The current default-bag grid is specialized, but other panel-family controllers remain generic. Focus, tooltips, chat bubbles, gamepad traversal and protected combat-HUD arrangements have not been behaviorally verified or completed.
- The helper has no GUI monitor selector, service, startup monitoring, automatic reconnect re-placement, or direct companion integration. This is intentionally a separate utility.
- Real in-client addon cold load, /reload, map lifecycle, combat/taint, Edit Mode, dynamic panel behavior, mixed-DPI viewport alignment, native addon handoff and physical hotplug are **not tested**. They remain shipping blockers.
