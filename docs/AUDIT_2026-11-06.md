# Release audit — 2026-11-06

## Follow-up critical audit (unreleased)

| Confirmed failure scenario | Then what? Impact | Fix and check |
|---|---|---|
| A routed panel throws on `SetPoint` during restore | `Reset` could stop on that panel, leave its anchors cleared and lose later restoration work | Panel restore is transactional, keeps its snapshot on failure and permits retry; Lua 5.1 injected restore failure/retry |
| A controller returns `false` while viewport apply succeeds | The addon could record a successfully applied layout even though the panel stayed at its old position | Aggregate panel-routing results; fail the apply and roll back viewport, panels and raw mouse; Lua 5.1 failed-controller check |
| A combat-deferred callback returns `false` without throwing | The queue silently drops a failed operation and diagnostics cannot explain the missing layout | Report false return/reason on flush; Lua 5.1 deferred-refusal check |
| A failed enable or preview follows a viewport refusal | Desired enabled state or preview confirmation could remain active without a usable layout | Return actual apply result, undo failed enable, and refuse failed preview; Lua 5.1 injected refusal checks |
| A top/left taskbar shifts `WINDOWPLACEMENT` workspace coordinates | Comparing those coordinates to monitor screen bounds can choose the wrong fallback; writing a screen rectangle into `WINDOWPLACEMENT` shifts the restored window | Capture `GetWindowRect`, compare screen-to-screen, restore original `WINDOWPLACEMENT`, then place a fallback with `SetWindowPos`; helper self-test and .NET build |
| Windows temporarily enumerates zero connected monitors during `watch` rollback | Safe-bounds selection previously threw before restoring styles, leaving WoW borderless and the saved state in place | Restore saved styles and `WINDOWPLACEMENT` without choosing a nonexistent display fallback; helper self-test covers empty enumeration |
| An already-enabled direct or combat-deferred reapply fails viewport/geometry validation | The layout could remain persisted as enabled with viewport/panels rolled back; World Map Escape state and subsequent recovery then disagree with the actual layout | Central rollback disables the desired state and restores panel, viewport, input and map Escape state; Lua 5.1 tests cover direct and post-combat failures |
| A selected display disconnects after exact native geometry was activated but leaves the addon running | A later display-size event could reuse the old union rectangles and silently compress the dual-screen split onto the smaller canvas | Revalidate the active handoff against Forever's physical screen size on every geometry calculation; clear the stale topology and use the normal failed-apply rollback; Lua runtime test covers the mismatch |
| A callback reports a concrete failure and returns false | `RunWhenSafe` overwrote the specific root cause with a generic rejection in `/forevermultimonitor diagnostics` | Error-generation tracking avoids duplicate reports; Lua 5.1 verifies the original error remains |
| The addon loads but no entry appears in WoW's AddOns settings | Users cannot discover or open the dashboard unless they know a slash command | Register the dashboard using the available legacy or modern AddOns category API during `ADDON_LOADED`, and retain slash openers; Lua 5.1 registration/open-path regression |
| A Forever Profession panel or forbidden Blizzard frame enters generic routing | Hooking/moving Blizzard-owned/load-on-demand UI can crash or taint the client; the reference intentionally yields Professions by default | Professions family is excluded on Forever; forbidden frames are skipped by discovery/routing; Lua 5.1 ownership tests |
| A one-display selection is used without opting into Beta 17's single-ultrawide workflow, or a normal span selects three-plus displays | The wrong topology could be activated, or WoW could be moved before addon calibration rejects the handoff | Default helper/addon mode requires exactly two displays; only explicit `--single-ultrawide` accepts one and emits a distinct 50/50 handoff mode; helper/Lua tests cover default and explicit counts |
| An addon installed on C: is selected for `--addon-dir` | The helper refused only by drive letter, blocking handoff for a common install path and forcing manual calibration | Accept any explicit absolute path after verifying the addon manifest/runtime files; pure helper test covers C: path contract |
| `/forevermultimonitor apply` is used to confirm a preview after the reapply fails | `KeepPreview()` reports failure and rolls back, then the command could still print “Layout preview confirmed.” | Print the command-level confirmation only when `KeepPreview()` returns true; source regression checks the result branch |
| A source check claims anchorless restoration without exercising an empty anchor list | An invented fallback anchor could pass a weak source-pattern assertion | Keep the Lua runtime case that restores a truly anchorless frame and make the static check require that runtime case |
| Monitor-selection rows or verification claims disagree across docs | A reviewer could mistake a duplicated scenario or stale “pass” statement for fresh shipping evidence | Remove duplicate selection rows and record only checks run against the final local state in README, changelog and test matrix |

## Additional confirmed native concurrency defect — fixed

Two nearly simultaneous `place` invocations could both observe absent `window-state.json`, then overwrite the same `.new` file or replace the recovery state. The second launch could permanently discard the first launch's original placement. Fixed using a unique temporary file and atomic non-overwriting `File.Move`. Concurrent actual-process fault injection is not yet performed; the code path has been inspected and the native helper rebuilt.

## Confirmed feature gaps — not silently represented as fixed

- Native calibration now maps exact four-edge MainMonitor/workspace rectangles for two-display offset, stacked and asymmetric layouts, plus the explicit equal single-ultrawide mode. These paths are simulated; real display and UI alignment are still unverified.
- The automatic panel drag-position recorder depends on frames actually invoking native OnDragStop. UI elements moved through alternate mechanisms do not necessarily persist.
- `/forevermultimonitor gather` now scans registry panels, `UIPanelWindows` and movable `UIParent` children, and the settings page has a button for the same action. Runtime tests cover those candidate sources and safety filters; live recovery remains unverified.
- The current default-bag grid is specialized, but other panel-family controllers remain generic. Focus, tooltips, chat bubbles, gamepad traversal and protected combat-HUD arrangements have not been behaviorally verified or completed.
- The helper has no GUI monitor selector, service, startup monitoring, automatic reconnect re-placement, or direct external helper integration. This is intentionally a separate utility.
- Real in-client addon cold load, `/reload`, slash commands, map lifecycle, combat/taint, Edit Mode, dynamic panel behavior, mixed-DPI viewport alignment, native addon handoff and physical hotplug are **not tested**. They remain shipping blockers.
